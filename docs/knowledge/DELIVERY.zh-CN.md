# CSG Lite 个人知识库使用与交付说明

本版将知识工作区、记忆管家、原生对话和 CSGClaw 知识连接放在同一个 CSG Lite 产品中。独立开发入口为 **http://localhost:11437/knowledge**，使用自己的存储目录。

## 启动交付包

GitHub 源码可按 [构建说明](README.zh-CN.md)启动。维护者在 Apple Silicon Mac 构建二进制后，可用 `scripts/package-knowledge-delivery.py <输出.zip>` 生成本节所述便捷包；源码下载 ZIP 本身不含可执行程序。便捷包仅适用于 **macOS arm64**，未签名、未公证，不是官方发行版。其他平台需自行构建和验证。

1. 完整解压 ZIP，保留 `CSGLite-Personal-Knowledge` 内的目录结构。
2. 双击 `scripts/start-knowledge-delivery.command`，或在交付包根目录的终端运行 `./scripts/start-knowledge-delivery.command`。
3. 终端显示启动信息后，在浏览器打开 **http://localhost:11437/knowledge**。终端窗口保留运行，按 **Control-C** 停止。

启动脚本只调用包内 `bin/csglite-knowledge-preview`，使用交付包目录下独立的 `local/knowledge-preview` 保存数据与临时文件；不自动下载依赖、导入凭据、复制模型或读取已有个人资料。模型需另行配置。若 macOS 拦截未签名程序，请核对来源后按系统提示允许本地打开；脚本不会自行修改系统安全设置。

11437 已占用时，脚本显示说明并退出，不会杀死、替换或改端口启动任何进程。已有预览可直接访问上述地址；要切换到交付包，请先在旧预览终端停止它。**本启动脚本不操作 11435。**

交付包不包含运行数据。开始使用后，移动或删除包目录前请先下载完整备份；ZIP 分享快照不能替代完整备份。

## 五分钟体验

以下步骤不需要模型，使用的都是虚构资料。

1. 打开知识库，主动载入虚构示例。系统不会扫描个人目录；也可新建空库后自行导入样本。
2. 在原始资料中查看“阅读活动初稿”和“阅读活动确认单”：初稿为 11 月 1 日、东区 101 室、18 人；确认单改为 11 月 3 日、西区 203 室、24 人。
3. 打开“待审提案”，核对两页变更及来源后接受。正式 Wiki 更新，原件仍保留；历史版本可查看，恢复历史会生成新的版本。
4. 浏览文件树、Wiki、双向链接和图谱，再打开“记忆管家”的“知识健康”。这里检查缺失来源、待复核页面、尚未整理的原件及正文相同的重复项，不代表 AI 已核实事实。
5. 在“导出与分享”下载 ZIP；再下载完整 JSON 备份并选择“恢复为新知识库”，核对恢复后的资料和版本。

演示中的待审稿是预置的虚构内容，不能作为模型已成功推理的证据。准备使用真实模型时，再按下一节配置。

## 使用记忆管家

1. 在 CSG Lite 的模型管理中准备可用文本模型，在“知识库设置”选择整理模型及其来源。
2. 打开“记忆管家”，选择 1–8 份有效原件。每次正文合计不超过 **64 KiB**；较大的文件请分批或拆分。
3. 点击“加入整理队列”。此时只建立任务，尚未调用模型。
4. 检查任务显示的模型与资料范围，点击“开始执行”。它将所选原件正文及最多 5 篇相关有效 Wiki 交给所选模型；云端模型会把这些内容发送给对应服务商。
5. 整理完成后点击“审阅草稿”，核对引用和变更，接受后才进入正式 Wiki。

同一库一次执行一个整理任务，单次最多等待 120 秒。等待中或执行中的任务可以取消；失败或取消后可以重新排队，再手动开始，总计最多尝试 3 次。运行中离开管家页面会中断请求；重启后遗留的运行状态会标记为失败，需明确重试。程序不会在启动时自动恢复执行。

来源撤回、相关 Wiki 更新或模型配置变化，会使旧任务失效；重新排队时重新核对当前资料。模型输出无效 JSON、缺少有效来源引用或超出范围时显示失败，不发布内容。

“记忆管家”在本版指资料整理、来源维护与待审流程。它没有定时主动整理、跨应用个人档案、自动长期偏好学习，也没有把所有聊天自动入库。

## 带知识对话，再把答案留下

在知识库点击“基于知识对话”，或在页面点击“围绕此页提问”，进入原生聊天的新会话。发送前能看到关联范围及所选模型；只有点击发送才调用模型。

每次发送重新筛选有效 Wiki，最多使用 5 页、24,000 字符正文，并保存当次引用版本和来源哈希。不会自动发送原件全文。使用云端模型时，所选 Wiki 摘录会随问题发送。解除关联或新建普通会话可以停止后续引用。

带有效来源引用的回答可以“保存为 Wiki 待审稿”。无引用、引用不属于当次上下文或来源已撤回时不能保存。引用校验只证明来源身份，仍需人工判断内容是否得到来源支持。

## 连接 CSGClaw

在库设置中开启读取权限，再进入“CSGClaw 连接”创建连接凭证；按 [接入指南](CSGCLAW.zh-CN.md) 在 Claw 中配置 `llm-wiki` 连接器并绑定 Agent。

凭证仅在创建时返回，离开页面后无法再次显示；遗失时撤销旧凭证并重新创建。一个凭证只对应一个库。读取和提交草稿可以分开授权，草稿权限不包含发布、删除或覆盖原件。

“已创建凭证”“已有访问记录”“Agent 完成任务”是不同状态。最近访问可能只是握手或工具探测，不代表 Agent 已生成答案。本版不自动启动 Claw、派发任务或追踪其运行进度。

## 分享与完整备份

| 项目 | 导出与分享 ZIP | 完整备份 JSON |
| --- | --- | --- |
| 主要用途 | 分享可读知识快照 | 保存和迁移该库的完整状态 |
| 包含内容 | 有效 Wiki、目录、页面版本和来源清单；可选所引用的有效原件 | 原件、Wiki、历史版本、提案、库配置、日志与整理任务 |
| 不包含 | 待审稿、失效 Wiki、历史版本、模型配置、连接凭证 | 连接凭证、模型文件、云端密钥、CSG Lite 聊天历史 |
| 恢复方式 | 不作为完整备份恢复 | 校验后建立新库，原库不变 |
| 本版限制 | 固定快照，已分享副本不能远程撤回 | 文件上限 20 MiB；包含尚未发布的内容，适合自行保管 |

恢复入口位于首次使用页，或已有库的“导出与分享”内。恢复会关闭新库的 Agent 读取及草稿权限，取消排队和运行中的整理任务，不导入连接凭证。模型名称等库设置会保留，但不代表本机已有该模型或可用授权。

恢复后的 Claw 提案仍保留作为记录；原连接不属于新库，旧待审稿不能直接接受。需要在新库创建连接、重新核对资料并生成新稿。

## 当前边界与常见问题

| 现象或需求 | 处理方式与边界 |
| --- | --- |
| 没有可选模型或整理失败 | 在模型管理检查本地运行状态或云端授权；预览与正式实例隔离，不复制正式凭据 |
| 文件无法导入 | 当前只接受 UTF-8 `.md` / `.txt`，单份正文不超过 2 MiB；尚无 PDF、DOCX 和 OCR |
| 健康检查没有问题 | 只表示当前结构检查未发现问题，不表示事实、时效和语义矛盾都已核实 |
| 待审稿接受失败 | 检查来源是否撤回、页面是否有新版本、Claw 凭证是否有效；不要强行覆盖现有版本 |
| 需要修改磁盘 Markdown | 使用知识库编辑器保存；外部文件修改尚不自动回写规范状态 |
| 想管理 1–2 TB 资料 | 本版尚无大规模索引与容量验证，不应将整批资料直接导入；后续需分块和增量索引设计 |
| 想远程访问、在线分享或多人协作 | 本版为同机个人使用，未实现远程知识服务、在线分享及企业成员权限 |
