# CSGClaw 接入个人知识库

本版提供本机 MCP 服务，让 CSGClaw 检索与阅读有效 Wiki，并将成果提交为待审稿。复用 Claw 的 `llm-wiki` 连接器，不需要把整个知识库复制到 Agent 工作目录。

适用前提：CSG Lite 开发版运行在 **127.0.0.1:11437**，CSGClaw 后端也运行在同一台电脑，并支持 HTTP MCP 连接器。知识连接与 Claw 的模型配置是两件事，均需分别确认。

## 1. 在 Lite 创建授权

1. 进入需要共享的知识库，在“知识库设置”开启“允许 Agent 读取知识”。如果需要成果回流，同时开启“允许 Agent 提交草稿”。
2. 打开“CSGClaw 连接”，为连接命名，选择有效期。界面提供 7、30、90、365 天，默认 30 天。
3. 默认只读；需要回流时勾选“允许提交待审稿”。
4. 点击“创建连接凭证”，将凭证复制到 Claw 的凭证字段。页面提供显示、复制凭证和复制 MCP 配置；离开页面后清除明文显示，服务端只保存哈希。

需要独立管理的 Agent 分别创建连接凭证和 Claw 资源。共享同一个凭证的 Agent 在 Lite 看来属于同一连接，不能按名称分别撤销。

## 2. 在 CSGClaw 配置连接器

1. 在 **资源 → 连接器** 新建 `llm-wiki` 资源，名称可填“CSG Lite · 虚构阅读计划”。
2. 填写 MCP 地址：`http://127.0.0.1:11437/api/knowledge/mcp`。
3. 选择 Bearer 认证，粘贴刚创建的凭证；不要把凭证发到 Agent 对话。
4. 测试连接并保存。只读连接应发现 `knowledge_search`、`knowledge_read`；允许草稿时还应发现 `knowledge_propose`。
5. 在指定 Agent 的连接器页面选择“从资源添加”，绑定上述资源并连接。

这是按 CSGClaw 公开源码中的连接器流程编写的配置说明，安装版本的菜单或能力可能不同。缺少入口时先核对客户端版本，不据此改动正在工作的 Claw 配置。[上游连接器说明](https://github.com/OpenCSGs/csgclaw/blob/a9492c456326c9de77697646de8f17f9919a855b/docs/tech/apps.zh.md)

如果客户端支持通用 MCP 配置，可以使用以下结构。`<知识库连接凭证>` 是占位符；实际值仅粘贴到本机客户端的私有配置中，不放入源码、聊天、截图或分享包。

```json
{
  "mcpServers": {
    "csglite-knowledge": {
      "transport": "streamable-http",
      "url": "http://127.0.0.1:11437/api/knowledge/mcp",
      "headers": {
        "Authorization": "Bearer <知识库连接凭证>"
      }
    }
  }
}
```

Lite 页面“复制 MCP 配置”会使用当前页面的实际地址，例如 `localhost`。连接时使用实际运行知识库的实例地址。容器内部的 `127.0.0.1` 指容器自身；本版有本机访问校验，远程机器、容器或代理部署不能仅通过替换地址宣称支持。优先由同机 Claw 后端建立连接，再通过其 Agent 连接器提供工具。

## 3. 用虚构资料验证

先在 Lite 的虚构示例中审阅接受活动确认稿，再向已绑定资源的 Agent 提问：

> 使用已连接的知识库，检索“活动安排”。说明当前时间、地点、人数，以及预算是计划还是实际支出。引用页面版本和来源；没有证据的内容请明确标出。

核对答案与 Wiki 是否一致，再检查 Lite 的“最近访问”。该记录只说明凭证发生了认证访问，可能来自初始化或测试连接；不能单独证明回答正确或任务完成。

启用待审稿权限后可以继续：

> 根据现有知识整理一页“活动准备清单”。每项保留来源引用，注明计划与已完成事实。仅提交知识库待审稿，提交后告诉我提案 ID，不要声称已经发布。

在 Lite 待审区检查稿件和来源，接受后再检索新页。这个过程才是“读取 → 产出 → 待审 → 接受 → 再使用”的完整验证；仅测试连接成功不能替代这一步。

## 工具合同

| 工具 | 输入与行为 | 返回和边界 |
| --- | --- | --- |
| `knowledge_search` | `query` 必填，`limit` 默认 5、范围 1–10 | 仅授权库中有效 Wiki；每项最多 600 字符，附页面 ID、版本、来源身份及哈希 |
| `knowledge_read` | `pageId` 必填，`offset` 默认 0 | 每次最多 8,000 Unicode 字符；有 `nextOffset` 时继续读取；不返回原件全文 |
| `knowledge_propose` | `taskId`、`runId`、`requestId`、`title`、`changes` | 创建 `pending` 提案；无直接接受、发布、删除或改写原件工具 |

修改现有页面时带上 `pageId` 及读取时的 `baseVersion`；新页使用空 `pageId` 和 `baseVersion: 0`。正文使用真实的 `[source:ID]`，`sourceIds` 与正文引用一致，不能编造来源。

同一连接重试提交时沿用同一 `requestId` 和完全相同的内容，会返回原提案而不重复创建；同一请求 ID 改了内容会报冲突，需要新 ID。每次提交最多 50 项修改、合计不超过 4 MiB；审阅前还会检查来源及当前页面版本。

MCP 版本为 **2025-06-18**，采用无会话状态的 HTTP POST / JSON-RPC。支持 `initialize`、`ping`、`tools/list`、`tools/call` 和初始化/取消通知；不提供 GET SSE 订阅。客户端请求需接受 `application/json` 与 `text/event-stream`，请求体为 `application/json`。初始化后使用协商的协议版本。若客户端不能完成这些交互，需兼容性适配；仅能访问 URL 不表示已兼容。

## 撤销、到期与恢复

- 在连接列表撤销后，该凭证的后续调用被拒绝；到期也停止访问。不能再次显示旧凭证，遗失后应撤销并新建。
- 关闭库读取权限会阻止全部连接读取；关闭草稿权限会阻止提交和接受 Claw 稿件。只读凭证不能通过调用隐藏工具获得写入能力。
- 接受 Claw 待审稿时会再次核对原连接、有效期、权限、来源和版本。撤销或到期之前提交的稿件也不能绕过检查；需要重新审核后通过有效连接提交新稿。
- 完整备份不包含连接凭证。恢复生成新库，权限关闭；旧连接及旧 Claw 待审稿不能自动获得新库授权。

本版没有自动向 Claw 派发任务、跨设备知识服务或企业成员权限。“打开 AI 应用”只是应用详情入口，不代表已安装、启动或建立连接。
